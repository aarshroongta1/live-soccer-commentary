A useful lesson can also go too far.

The save comparison removes an unsupported near-post detail while retaining the actual save. On the Barcelona clip, the same lesson adds unnecessary uncertainty and repetitive analysis. A memory should earn its place through checks on subsequent tasks.

This is a small application-level learning loop: past failure, correction, persistent instruction, then new calls. It is an experiment in improving an agent’s behavior with existing models.

What actually ran

GPT-5.4 Mini distilled one lesson from a retained November 7 failure and its coding-agent correction. That lesson was frozen before this comparison. Three development clips were selected in advance: a crowded goalmouth, a dribble and finish, and a real-save control. Each received one baseline call and one memory call, with the same model, observations, output schema, and compact writer instructions. Only the saved lesson changed.

Results, costs, and limitations

This compares a compact experimental writer, not the repo’s current production role prompts. It uses saved model perception and complete clip context. No fresh vision, search, speech, training, or RL ran. All three clips belong to the existing 15-clip development suite; they are not an independent benchmark.

Two memory scripts meet the 35-word target; the Barcelona memory script does not. Citation-ID checks only establish that IDs exist. They do not prove factual support. The favorable save pair is one stochastic sample, not evidence of a repeatable accuracy gain.

An initial pilot exposed conflicting legacy script-length instructions. Three of its six writer outputs failed parsing. Those failures are retained. After the format fix, the same frozen lesson was reused for all six new writer calls, without retries or selecting a winning generation.

Correction and comparison review were performed by coding agents. No independent human ratings were collected. A future iteration should refine the overly broad lesson and test that revision on different cases.

Why I built this

Noeri’s work on specialized agents that improve from real tasks and corrections prompted this experiment. The question here is deliberately small: can an agent carry a useful correction into its next job, and can we catch when that lesson hurts? This runs independently of Noeri and uses no Noeri API.
